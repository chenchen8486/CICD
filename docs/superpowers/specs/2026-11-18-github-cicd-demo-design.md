# GitHub CI/CD 演示项目设计

## 目标

　　在当前仓库新增 `demo/` 中的命令行加法器，用真实 GitHub 仓库串起本地开发、自动测试、构建产物、拉取请求、合并和标签发布。读者第一次接触 CI/CD，因此每个环节都要能观察结果，并能在本地重复运行相同命令。

## 方案比较

- 单工作流加 GitHub Releases：一个文件展示测试、构建和发布，依赖最少，本次采用。
- 分离 CI 与发布工作流：职责更清楚，但初学者需要同时跟踪两个文件，后续可以再拆分。
- 发布到 PyPI 或部署到服务器：链路更接近特定生产场景，但增加账号、凭据和环境配置，不适合作为第一次实操。

## 实现约定

- 程序只提供两个数字相加，使用 Python 标准库 `argparse`。
- 测试使用标准库 `unittest`，不安装第三方依赖。
- 使用 `zipapp` 生成单个 `.pyz` 文件，用户下载后可直接用 Python 运行。
- GitHub Actions 在 `main` 推送、拉取请求、`v*` 标签和手动触发时运行测试与构建。
- 仅标签推送执行发布任务，将同一个构建产物附加到 GitHub Release。
- 首个版本搭建完成后，由用户在功能分支上做小改动、发起拉取请求、观察检查、合并并发布 `v0.1.0`。

## 边界

　　本次不引入代码规范工具、测试覆盖率、矩阵测试、容器、云服务器或真实业务部署。分支保护规则作为拉取请求环节的界面操作单独设置，不用自动化绕过人工确认。
